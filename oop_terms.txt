ОСНОВНЫЕ ПОНЯТИЯ ООП И C++ ДЛЯ ЗАЩИТЫ ЛАБОРАТОРНОЙ №1

Требования из PDF, на которые опирается этот список: объяснять конструкции C++,
поведение программы и подходы безопасной разработки; описать классы, архитектуру
(UML) и паттерн; понимать используемые технологии; не допускать утечек памяти и
падений из-за необработанных исключений.


=== 1. КЛАСС, ОБЪЕКТ, МЕТОД ===

Класс
    Описание нового типа: какие данные он хранит и что умеет делать.
    Сам по себе класс - это чертёж, а не данные.
    Пример: class DirectoryWalker { ... };

Объект
    Конкретная сущность, созданная по классу. Занимает память и хранит свои данные.
    Пример: DirectoryWalker w;

Экземпляр (instance)
    То же, что объект, но с акцентом на его связь с классом:
    "w - экземпляр класса DirectoryWalker".
    Метод CryptoManager::instance() назван так потому, что возвращает
    единственный экземпляр класса. Само слово instance не ключевое, это просто имя.

Поле (член данных, переменная-член)
    Переменная внутри класса. У каждого объекта свои значения полей.
    Пример: QStringList filesOperations;

Метод (функция-член)
    Функция внутри класса. Работает с полями объекта, у которого вызвана.
    Пример: w.walker(path);

this
    Указатель на текущий объект внутри метода. Запись filesSkip внутри метода
    равносильна this->filesSkip.

Объявление и определение
    Объявление сообщает компилятору, что функция существует (обычно в .h):
        void walker(const QString &path);
    Определение содержит её тело (обычно в .cpp):
        void DirectoryWalker::walker(const QString &path) { ... }

Оператор :: (разрешение области видимости)
    Показывает, чему принадлежит имя: DirectoryWalker::walker, CryptoManager::instance.


=== 2. ЧЕТЫРЕ ПРИНЦИПА ООП ===

Инкапсуляция
    Данные и работа с ними собраны в классе, а внутреннее устройство скрыто.
    Пример: filesSkip закрыт (private), прочитать его можно только через GetFilesSkip().

Наследование
    Новый класс получает поля и методы существующего и может их дополнять.
    Пример: class Student : public Person { ... };

Полиморфизм
    Один и тот же вызов работает по-разному в зависимости от настоящего типа объекта.
    Обычно реализуется через virtual-методы.

Абстракция
    Выделяем важное и скрываем детали. Вызывающему коду достаточно знать
    encryptFile(...), а не то, как устроен AES.

Абстракция и полиморфизм: сравнение

=== 3. МОДИФИКАТОРЫ ДОСТУПА ===

public      Доступно всем: и снаружи класса, и внутри.
protected   Доступно самому классу и его наследникам, снаружи недоступно.
private     Доступно только самому классу (и его друзьям, friend).

                    внутри класса    наследник    снаружи
    public              да              да           да
    protected           да              да           нет
    private             да              нет          нет

class и struct
    Разница в доступе по умолчанию: в class - private, в struct - public.

friend
    Функция или класс, которым разрешён доступ к закрытым членам этого класса.


=== 4. КОНСТРУКТОРЫ, ДЕСТРУКТОР, КОПИРОВАНИЕ ===

Конструктор
    Вызывается автоматически при создании объекта и подготавливает его к работе.
    Имя совпадает с именем класса, возвращаемого типа нет.

Конструктор по умолчанию
    Конструктор, который можно вызвать без аргументов: CryptoManager();

Список инициализации
    Задаёт значения полей до входа в тело конструктора:
        Point(int a) : x(a) {}

Деструктор
    Вызывается автоматически при уничтожении объекта и освобождает ресурсы.
    Записывается с тильдой: ~MyClass(); Параметров нет, у класса он один.

Конструктор копирования
    Создаёт новый объект как копию существующего:
        MyClass(const MyClass &other);
    Вызывается, например, так: MyClass b = a;

Оператор присваивания копированием
    Копирует данные в уже существующий объект:
        MyClass &operator=(const MyClass &other);
    Вызывается так: b = a;

    Как отличить: MyClass b = a;  - создаётся новый объект, конструктор копирования.
                  b = a;          - b уже существует, operator=.

Поверхностное и глубокое копирование
    Поверхностное копирует сам указатель, и два объекта владеют одной памятью.
    Глубокое выделяет отдельную память и копирует данные.

Конструктор и присваивание перемещением
    MyClass(MyClass &&other); забирают ресурсы у временного объекта, не копируя их.

Правило трёх (пяти)
    Если классу нужен свой деструктор, конструктор копирования или operator=, то,
    скорее всего, нужны все три (а с перемещением - пять).

= default
    Просит компилятор создать стандартную реализацию:
        CryptoManager() = default;

= delete
    Запрещает функцию. Попытка её вызвать - ошибка компиляции:
        CryptoManager(const CryptoManager &) = delete;

default в switch - другое значение того же слова: ветка "все остальные случаи".

RAII
    Ресурс захватывается в конструкторе и освобождается в деструкторе, поэтому
    освобождение произойдёт и при выходе из функции, и при исключении.
    Пример: QFile закрывает файл в своём деструкторе.


=== 5. ПЕРЕДАЧА ДАННЫХ, УКАЗАТЕЛИ И ССЫЛКИ ===

Передача по значению
    void f(QString s);  Функция получает копию, оригинал не меняется.

Указатель
    Переменная, хранящая адрес другого объекта.
        int x = 5;
        int *p = &x;    // & здесь - взятие адреса
        *p = 7;         // * здесь - разыменование, теперь x == 7
    Может быть равен nullptr и может быть перенаправлен на другой объект.

Ссылка
    Другое имя уже существующего объекта.
        int x = 5;
        int &r = x;     // & здесь - объявление ссылки
        r = 7;          // теперь x == 7
    Инициализируется сразу, не бывает нулевой, не перенаправляется на другой объект.
    Там, где объект доступен по своему имени, с ним и работают напрямую, ссылка не нужна.
    Ссылка нужна, когда объект надо передать в другую функцию или вернуть из неё:
    внутри другой функции имя чужой переменной недоступно, а передача по значению
    создаёт копию.

Обращение к членам класса
    Через объект или ссылку - точка:   w.walker(path);
    Через указатель - стрелка:         p->walker(path);   // то же, что (*p).walker(path)

Передача по указателю
    void f(QString *s);   Вызов: f(&text);  Нужно проверять на nullptr.

Передача по ссылке
    void f(QString &s);   Вызов: f(text);   Функция меняет оригинал.
    Пример: параметр QString &error, чтобы вернуть текст ошибки.

Передача по константной ссылке
    void f(const QString &s);  Нет копирования, и менять объект нельзя.
    Пример: void walker(const QString &path);

Висячие указатель и ссылка
    Указывают на уже уничтоженный объект, обращение к ним - неопределённое поведение.
    Поэтому нельзя возвращать ссылку на обычную локальную переменную.
    В instance() это безопасно: static-объект живёт до конца программы.

Стек и куча
    Стек: локальные переменные, память освобождается автоматически при выходе из блока.
    Куча: память, выделенная через new, живёт до явного delete.

new и delete
    MyClass *p = new MyClass;    delete p;
    Для массивов: int *a = new int[10];    delete[] a;

Утечка памяти
    Память выделена, но не освобождена, и указателя на неё больше нет.
    Проверяется инструментами, например Dr. Memory.

Умные указатели
    std::unique_ptr (один владелец), std::shared_ptr (общее владение).
    Освобождают память автоматически.


=== 6. КЛЮЧЕВЫЕ СЛОВА ===

static - значение зависит от места:
    Поле класса      Одно на все объекты класса, принадлежит классу.
    Метод класса     Вызывается без объекта: CryptoManager::instance();
                     нет this, обычные поля напрямую недоступны.
    Локальная        Создаётся один раз при первом проходе, живёт до конца программы.
    переменная       Пример: static CryptoManager manager;
                     С C++11 такое создание потокобезопасно.
    Глобальная       Видна только в своём .cpp файле.
    переменная или
    функция

    Подробнее:
    static меняет одно из двух: сколько живёт сущность либо кому она принадлежит
    и кому видна.
    - Статическое поле существует, даже если объектов нет. Обращаются к нему через
      имя класса: User::count. Если забыть определение в .cpp, при линковке будет
      ошибка undefined reference. С C++17 можно написать прямо в классе:
      inline static int count = 0;
    - Статический метод не может напрямую обращаться к обычным полям и методам:
      нет this, значит, неизвестно, чьи они. Его нельзя объявить const или virtual.
      При этом он имеет доступ к private-членам своего класса, поэтому instance()
      может вызвать закрытый конструктор.
    - Строка static int number = 0; присваивает 0 только при первом проходе,
      а не при каждом вызове функции.
    - С C++11 потокобезопасно только создание локальной static-переменной.
      Дальнейшие изменения из нескольких потоков нужно защищать отдельно.
    - static и const - разные вещи, их можно сочетать: static const int keySize = 32;

    Примеры:
        // поле класса: одно на все объекты
        class User
        {
        public:
            User(){ count++; }
            static int count;
        };
        int User::count = 0;    // определение в .cpp

        User a;
        User b;
        // User::count == 2

        // метод класса: вызов без объекта
        CryptoManager &manager = CryptoManager::instance();

        // локальная переменная: значение сохраняется между вызовами
        int nextNumber(){
            static int number = 0;
            number++;
            return number;      // при вызовах вернёт 1, 2, 3...
        }

        // глобальные имена: видны только в этом .cpp файле
        static const int keySize = 32;
        static void helper(){ }

    Для чего нужен вызов метода без объекта:

    1. Объект ещё нельзя получить иначе.
    Обычный метод вызывается у готового объекта. Но в Singleton конструктор закрыт,
    поэтому снаружи объект не создать:
        CryptoManager m;                 // ошибка: конструктор private
    Если бы instance() был обычным методом, его не у чего было бы вызвать.
    Статический метод вызывается через имя класса, а внутри него закрытый конструктор
    доступен, потому что это метод самого класса:
        CryptoManager &CryptoManager::instance(){
            static CryptoManager manager;   // здесь создавать объект можно
            return manager;
        }

        // снаружи
        CryptoManager &m = CryptoManager::instance();
    Сначала вызов без объекта выдаёт объект, а дальше с ним работают как обычно:
    m.encryptFile(...).

    2. Методу не нужны данные объекта.
    Два способа проверить, существует ли файл:
        // через объект: он хранит путь внутри себя
        QFile file(path);
        file.exists();

        // без объекта: путь передан параметром
        QFile::exists(path);
    Результат одинаковый, но во втором случае не нужно создавать объект только ради
    одного вызова. Обычно такой метод не использует поля объекта: он получает данные
    через параметры и возвращает результат, как обычная функция. В класс его помещают,
    потому что он связан с этим классом по смыслу.

    Как определить, какой метод нужен - посмотреть, использует ли он поля объекта:
        DirectoryWalker::walker          да, заполняет filesOperations и filesSkip - обычный
        DirectoryWalker::GetFilesSkip    да, читает filesSkip                      - обычный
        CryptoManager::instance          нет, сам выдаёт объект                    - статический
        QFile::exists(path)              нет, путь приходит параметром             - статический

const - "нельзя менять":
    Переменная             const int size = 16;
    Параметр-ссылка        const QString &path
    Метод                  QStringList GetFilesSkip() const;
                           метод не меняет поля объекта.
    Указатель на const     const int *p;        значение менять нельзя, p можно.
    const-указатель        int *const p;        p менять нельзя, значение можно.

    Примеры:
        const int size = 16;
        size = 32;              // ошибка компиляции

        void print(const QString &path){
            path.clear();       // ошибка компиляции: path менять нельзя
        }

        int a = 1;
        int b = 2;

        const int *p1 = &a;
        *p1 = 5;                // ошибка: значение менять нельзя
        p1 = &b;                // можно

        int *const p2 = &a;
        *p2 = 5;                // можно
        p2 = &b;                // ошибка: указатель менять нельзя

    Подробнее:
    const проверяется при компиляции: попытка изменить значение просто не скомпилируется.
    - Объявление указателя удобно читать справа налево:
      const int *p   - p это указатель на int, который нельзя менять через p;
      int *const p   - p это неизменяемый указатель на int.
    - В const-методе this указывает на константный объект, поэтому менять поля нельзя.
      Вызывать из него можно только другие const-методы этого объекта.
    - У const-объекта можно вызывать только const-методы. Поэтому геттеры объявляют
      const: иначе их нельзя будет вызвать через const DirectoryWalker &.
    - Исключение - поля с пометкой mutable: их можно менять и в const-методе.
    - Параметр по константной ссылке защищает оригинал и не создаёт копию.

virtual
    Метод, который можно переопределить в наследнике; нужный вариант
    выбирается во время выполнения.
    Без virtual версию выбирает компилятор по объявленному типу, а с virtual -
    программа по настоящему типу объекта. Работает при вызове через указатель или
    ссылку. При передаче по значению остаётся только часть базового класса (срезка).
    Обычно это реализовано через таблицу виртуальных функций (vtable): объект хранит
    скрытый указатель на таблицу адресов методов своего класса.
    Пример:
        class Cipher
        {
        public:
            virtual ~Cipher() = default;
            virtual QString name() const{ return "unknown"; }
        };

override
    Просит компилятор проверить, что метод действительно переопределяет
    метод базового класса.
    Без override опечатка в имени или забытый const молча создадут новый отдельный
    метод, и вызов через базовый класс пойдёт в старую версию. С override компилятор
    сообщит об этом ошибкой. Писать его не обязательно, но полезно.
    Пример:
        class AesCipher : public Cipher
        {
        public:
            QString name() const override{ return "AES"; }
            // QString name() override;  ошибка: забыт const, переопределять нечего
        };

Чисто виртуальный метод и абстрактный класс
    virtual void run() = 0;  Создать объект класса с таким методом нельзя.
    Запись = 0 означает, что базовый класс задаёт только сам метод, а реализацию
    обязаны дать наследники. Наследник, не реализовавший такой метод, тоже остаётся
    абстрактным. Указатели и ссылки на абстрактный класс создавать можно.
    Пример:
        class Task
        {
        public:
            virtual ~Task() = default;
            virtual void run() = 0;
        };

        Task t;                 // ошибка компиляции: класс абстрактный

Виртуальный деструктор
    Нужен базовому классу, если объект наследника удаляют через указатель на базовый.
    С ним при delete сначала вызывается деструктор наследника, затем базового класса.
    Без него это неопределённое поведение: на практике деструктор наследника обычно
    не вызывается, и его ресурсы могут утечь. Правило: есть virtual-методы -
    сделай деструктор виртуальным.
    Пример:
        Cipher *p = new AesCipher;
        delete p;               // без virtual ~Cipher() - неопределённое поведение

explicit
    Запрещает неявное преобразование через конструктор.
    Конструктор с одним параметром без explicit позволяет компилятору незаметно
    превращать значение в объект, например передать 16 в функцию, ждущую Buffer.
    Такие ошибки трудно заметить, поэтому такие конструкторы обычно делают explicit.
    Пример:
        class Buffer
        {
        public:
            explicit Buffer(int size);
        };

        Buffer a(16);           // можно
        Buffer b = 16;          // ошибка компиляции, без explicit было бы можно

inline
    Разрешает определять функцию в заголовке. Методы, написанные прямо внутри
    класса (как GetFilesSkip), неявно inline.
    Обычно у функции может быть только одно определение на всю программу. Если .h с
    обычной функцией включить в два .cpp, определений станет два, и линковка сломается.
    inline разрешает такие одинаковые определения. Встраивание кода на место вызова
    компилятор решает сам, inline его не гарантирует.
    Пример:
        // в .h: без inline будет ошибка линковки, если .h включён в несколько .cpp
        inline int square(int x){ return x * x; }

auto
    Компилятор сам выводит тип переменной по её начальному значению, поэтому без
    инициализации auto писать нельзя. Тип определяется при компиляции и потом не
    меняется. Просто auto отбрасывает ссылку и верхний const и создаёт копию; чтобы
    копии не было, пишут const auto &.
    Пример:
        auto size = 16;                             // int
        auto list = walker.GetFilesOperations();    // QStringList

reinterpret_cast
    Трактует те же байты как другой тип. Опасен, применять только осознанно.
    Сами данные не меняются и не проверяются, компилятор верит на слово. Обращение к
    объекту через указатель на неподходящий тип может быть неопределённым поведением.
    Смотреть на данные как на байты (char, unsigned char) разрешено, поэтому его
    применяют для передачи данных из QByteArray в библиотеки вроде Crypto++.
    Пример:
        QByteArray data("abc");
        const unsigned char *bytes =
            reinterpret_cast<const unsigned char *>(data.constData());

static_cast
    Обычное явное преобразование типов, проверяется при компиляции.
    Безопаснее записи (int)value: заметнее в коде и не выполнит заведомо бессмысленное
    преобразование. Во время выполнения проверок нет: при приведении указателя базового
    класса к наследнику правильность настоящего типа не проверяется. Для такой проверки
    есть dynamic_cast.
    Пример:
        double value = 3.7;
        int number = static_cast<int>(value);       // 3, дробная часть отброшена


=== 7. ДРУГИЕ КОНСТРУКЦИИ ЯЗЫКА ===

Перегрузка функций
    Одно имя, разные параметры.

Перегрузка операторов
    Своё поведение для операторов класса, например operator=.

Шаблон (template)
    Код, общий для разных типов. Пример: GCM<AES>, QList<QString>.

Пространство имён (namespace)
    Защищает от совпадения имён. Пример: CryptoPP::SecByteBlock, std::string.

Исключение (try, catch, throw)
    Способ сообщить об ошибке. Необработанное исключение завершает программу аварийно.

Время жизни объекта
    От конструктора до деструктора.

Заголовочный файл и файл реализации
    .h - объявления, .cpp - реализация.

Защита от повторного включения (include guard)
    #ifndef CRYPTO_MANAGER_H / #define CRYPTO_MANAGER_H / #endif
    Не даёт включить один заголовок дважды в один .cpp файл.

Компиляция и компоновка (линковка)
    Компилятор превращает каждый .cpp в объектный файл, компоновщик собирает их
    и библиотеки в .exe.

Неопределённое поведение (UB)
    Код, результат которого стандарт не определяет: выход за границы массива,
    обращение к удалённому объекту.


=== 8. ПАТТЕРНЫ И АРХИТЕКТУРА ===

Паттерн проектирования
    Типовое решение часто встречающейся задачи проектирования.

Singleton (одиночка)
    Гарантирует один объект класса и единую точку доступа к нему. Составные части:
        закрытый конструктор                 снаружи объект создать нельзя;
        удалённое копирование                нельзя получить второй объект копией;
        статический метод instance()         возвращает ссылку на объект;
        static-объект внутри instance()      создаётся один раз.
    Минус: глобальное состояние усложняет тестирование и скрывает зависимости.

UML-диаграмма классов
    Показывает классы, их поля, методы и связи между ними.
    Обозначения доступа: + public, - private, # protected.
    Статические члены подчёркиваются.

Связи между классами в UML
    Ассоциация       Один класс знает о другом и использует его.
    Зависимость      Класс временно использует другой (пунктирная стрелка).
    Агрегация        Целое содержит часть, но часть может жить отдельно (пустой ромб).
    Композиция       Часть не живёт без целого (закрашенный ромб).
    Наследование     Сплошная линия с пустым треугольником.


=== 9. ТЕХНОЛОГИИ ПРОЕКТА ===

Qt
    QString - строка; QFile - работа с файлом; QDir, QFileInfo - папки и сведения о файлах.
    QSaveFile пишет во временный файл и заменяет исходный только при commit(), поэтому
    сбой посреди записи не портит исходный файл.

Crypto++
    Библиотека криптографических алгоритмов.

AES-256-GCM
    Симметричный шифр: один ключ для шифрования и расшифрования.
    GCM дополнительно проверяет целостность данных.

PBKDF2
    Получает ключ из пароля. Намеренно медленный, что затрудняет подбор пароля.

Соль (salt)
    Случайные байты для получения ключа: один и тот же пароль даёт разные ключи.

Nonce
    Случайное значение для шифра. С одним ключом повторять его нельзя.

Тег (tag)
    Контрольная метка: не совпала - неверный пароль или файл повреждён.

Безопасная разработка
    Проверять входные данные и результаты операций, не падать на ошибках, не допускать
    утечек, не хранить ключи и пароли дольше необходимого, не изобретать свои шифры.
